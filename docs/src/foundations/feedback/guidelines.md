# 피드백

피드백은 사용자의 행동과 가까운 위치에서, 결과의 중요도에 맞게 제공합니다.

## 어떤 컴포넌트를 쓰나요

| 상황                                   | 먼저 선택할 표현                   |
| -------------------------------------- | ---------------------------------- |
| 입력값을 고쳐야 함                     | FieldError와 입력 가까운 설명      |
| 흐름을 막지 않는 작업 완료             | Toast                              |
| 되돌릴 수 있는 작업                    | Toast의 Undo 액션과 실제 복구 처리 |
| 계속 보여야 하는 화면 수준 안내        | Banner 또는 Message                |
| 짧은 비동기 처리                       | Spinner와 상태 문장                |
| 진행량이 알려진 처리                   | Progress                           |
| 결정 후에만 진행할 수 있는 위험한 행동 | Alert Dialog                       |

알림을 무조건 Dialog로 표시하지 않습니다. 반대로 사용자가 반드시 읽어야 하는 조건을 금방 사라지는 Toast에만 두지 않습니다.

## 액션의 책임

Undo 버튼은 알림을 닫는 것만으로 복구를 완료하지 않습니다. 실제 데이터를 되돌린 뒤 결과를 반영합니다. Dismiss all은 알림 목록을 정리하는 행동이며 작업 자체를 취소하는 의미로 쓰지 않습니다.

## 확인할 것

같은 결과를 여러 경로에서 중복으로 알리지 않습니다. 로딩에서 성공·실패로 이어지는 문장을 연결하고, 알림이 사라져도 필요한 상태는 본문에 남깁니다. Toast의 Escape는 최신 알림부터 하나씩 닫히는 기존 동작을 유지합니다.
